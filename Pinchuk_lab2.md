## Что такое API-first

API-first — это подход, при котором **контракт API разрабатывается и фиксируется до написания кода реализации**.
Код генерируется по спецификации, а не пишется вручную и не выводится из реализации.

```
Спецификация (.graphql / .proto)
        ↓
   Кодогенерация
        ↓
   Сгенерированные модели, резолверы
        ↓
   Реализация бизнес-логики поверх сгенерированного кода
```

## 1. GraphQL — контракт с UI

### Спецификация: `go-init-manager/api/graphql/go-init.graphql`

Весь публичный API для фронтенда описан в одном файле. Сначала — контракт, потом — реализация.

```graphql
# Типы данных — описывают структуру ответов
type ServiceTemplate {
  id:        ID!
  name:      String!
  status:    TemplateStatus
  zipUrl:    String
  createdAt: String!
}

enum TemplateStatus {
  PENDING
  PROCESSING
  COMPLETED
  FAILED
}

# Входные типы — описывают параметры запросов
input CreateTemplateInput {
  name:      String!
  endpoints: [EndpointInput]
  database:  DatabaseInput
  docker:    DockerInput
  advanced:  AdvancedInput
}

# Контракт операций — что может делать клиент
type Query {
  getTemplate(id: ID!):              TemplateResponse!
  getRecentTemplates(limit: Int = 5): TemplatesResponse!
}

type Mutation {
  createTemplate(input: CreateTemplateInput!): TemplateResponse!
}
```

### Кодогенерация: `make gqlgen`

Из `.graphql`-файла генерируются Go-структуры и интерфейсы:

```bash
make gqlgen
# Installing gqlgen...
# Generating GraphQL code from go-init.graphql...
# Running go mod tidy...
```

Конфигурация генератора — `tools/gqlgen.yml`:

```yaml
schema:
  - ../api/graphql/go-init.graphql        # источник — спецификация

exec:
  filename: ../pkg/api/graphql/generated.go  # сгенерированный сервер

model:
  filename: ../pkg/api/graphql/model/models_gen.go  # сгенерированные модели

resolver:
  dir: ../pkg/api/graphql
```

### Результат: `pkg/api/graphql/model/models_gen.go`

Файл генерируется автоматически — **вручную не редактируется**:

```go
// Code generated by github.com/99designs/gqlgen, DO NOT EDIT.

type CreateTemplateInput struct {
    Name      string           `json:"name"`
    Endpoints []*EndpointInput `json:"endpoints,omitempty"`
    Database  *DatabaseInput   `json:"database,omitempty"`
    Docker    *DockerInput     `json:"docker,omitempty"`
    Advanced  *AdvancedInput   `json:"advanced,omitempty"`
}

type ServiceTemplate struct {
    ID        string          `json:"id"`
    Name      string          `json:"name"`
    Status    *TemplateStatus `json:"status,omitempty"`
    ZipURL    *string         `json:"zipUrl,omitempty"`
    CreatedAt string          `json:"createdAt"`
}

type TemplateStatus string

const (
    TemplateStatusPending    TemplateStatus = "PENDING"
    TemplateStatusProcessing TemplateStatus = "PROCESSING"
    TemplateStatusCompleted  TemplateStatus = "COMPLETED"
    TemplateStatusFailed     TemplateStatus = "FAILED"
)
```

### Реализация резолверов поверх сгенерированного кода

Разработчик реализует только **бизнес-логику** — сигнатуры методов уже определены генератором:

```go
// pkg/api/graphql/go-init.go — реализация резолверов

// CreateTemplate is the resolver for the createTemplate field.
func (r *mutationResolver) CreateTemplate(
    ctx context.Context,
    input model.CreateTemplateInput,
) (*model.TemplateResponse, error) {
    return r.Service.CreateTemplate(ctx, input)
}

// GetRecentTemplates is the resolver for the getRecentTemplates field.
func (r *queryResolver) GetRecentTemplates(
    ctx context.Context,
    limit *int,
) (*model.TemplatesResponse, error) {
    return r.Service.GetRecentTemplates(ctx, limit)
}
```

## 2. gRPC — контракт для межсервисного взаимодействия

### Спецификация: `api/external/grpc/go-init-manager.proto`

Межсервисный API описан в `.proto`-файле — тот же принцип: сначала контракт.

```protobuf
syntax = "proto3";
package pb;

option go_package = "go-init/pkg/api/grpc/go-init-generate;go_init_generate";

// Контракт: generator сервис вызывает этот метод у manager,
// когда заканчивает генерацию
service ManagerService {
  rpc UpdateGenerationStatus(UpdateGenerationStatusRequest)
      returns (UpdateGenerationStatusResponse);
}

message UpdateGenerationStatusRequest {
  string request_id = 1;  // ID запроса на генерацию
  string status     = 2;  // "completed" / "failed"
  string zip_url    = 3;  // URL архива в MinIO (если успешно)
}

message UpdateGenerationStatusResponse {
  bool success = 1;
}
```

### Кодогенерация: `make protoc`

```bash
make protoc
# Installing protobuf plugins...
# Generating protobuf for go-init-manager.proto...
# Running go mod tidy...
```

Из `.proto` генерируются Go-файлы в `pkg/api/grpc/`:
- `go-init-manager.pb.go` — структуры сообщений
- `go-init-manager_grpc.pb.go` — серверный и клиентский интерфейсы

---

## 3. Сравнение подходов генерации

| | GraphQL (gqlgen) | gRPC (protobuf) |
|---|---|---|
| Спецификация | `*.graphql` | `*.proto` |
| Команда | `make gqlgen` | `make protoc` |
| Конфиг | `tools/gqlgen.yml` | параметры `protoc` в Makefile |
| Генерируется | модели + резолверы + сервер | структуры + client/server stub |
| Используется для | UI ↔ manager | manager ↔ generator ↔ publisher |

## 4. Исследование API через Postman

Запустить сервис локально:

```bash
# Поднять инфраструктуру
cd virtualization && docker compose -f docker-compose-local.yml up -d

# Запустить go-init-manager
cd go-init-manager && make run
```

Сервис доступен на `http://localhost:60013`.

### Загрузка схемы в Postman

**Способ 1 — через introspection** (автоматически подтягивает все типы):

1. Новый запрос → тип **GraphQL**
2. URL: `http://localhost:60013/graphql`
3. Body → GraphQL → кнопка **"Load Schema"**

**Способ 2 — через SDL по URL** (не зависит от introspection):

- Import → Link → `http://localhost:60013/graphql/schema.graphql`

### Примеры запросов

**Создать шаблон сервиса:**

```graphql
mutation CreateTemplate {
  createTemplate(input: {
    name: "my-service"
    endpoints: [
      { protocol: REST,  role: SERVER }
      { protocol: GRPC, role: SERVER }
    ]
    database: { type: POSTGRESQL }
    docker:   { imageName: "my-service" }
    advanced: { enableAuthentication: true, generateSwaggerDocs: true }
  }) {
    success
    message
    template {
      id
      name
      status
      createdAt
    }
  }
}
```

**Получить список последних шаблонов:**

```graphql
query RecentTemplates {
  getRecentTemplates(limit: 5) {
    success
    templates {
      id
      name
      status
      zipUrl
      createdAt
    }
  }
}
```

**Получить статус конкретного шаблона:**

```graphql
query GetTemplate {
  getTemplate(id: "1") {
    success
    template {
      id
      name
      status
      zipUrl
      error
    }
  }
}
```

Встроенный GraphQL playground доступен по адресу `http://localhost:60013/playground` — открывает интерактивный редактор с документацией по схеме.

## 5. Ключевые преимущества API-first в проекте

1. **Единый источник истины** — `.graphql` и `.proto` файлы в `api/` — это и документация, и спецификация, и основа для кодогенерации одновременно.

2. **Независимая разработка** — фронтенд и бэкенд могут разрабатываться параллельно, опираясь на зафиксированный контракт.

3. **Нет расхождений** — бизнес-логика пишется поверх сгенерированных интерфейсов, компилятор Go гарантирует соответствие реализации контракту.

4. **Воспроизводимость** — повторный запуск `make gqlgen` / `make protoc` всегда даёт тот же результат из той же спецификации.
